About ResumeCraft

An enterprise-grade, full-stack web application designed to democratize professional career access through intelligent resume creation, ATS quality evaluation, and application lifecycle tracking.

Problem Statement
“Helps individuals create professional resumes and improve their access to employment opportunities.”

Many students, fresh graduates, and career changers struggle to format industry-standard resumes that successfully pass modern Applicant Tracking Systems (ATS). ResumeCraft solves this by providing structured guided inputs, 4 recruiter-approved templates, objective quality scoring with action verb suggestions, and a centralized job application tracker.

System Architecture
Presentation Layer
Built with plain HTML5, CSS3, vanilla JavaScript (ES6+), and Bootstrap 5. Provides responsive layouts, live debounced split-screen previews, modal forms, and print-specific A4 stylesheets without heavy frontend frameworks.
Application Layer
Node.js and Express.js RESTful API architecture. Implements session-based authentication with MySQL persistence, CSRF protection, brute-force rate limiting, input validation via express-validator, and PDFKit server-side vector generation.
Data Layer
Relational MySQL 8.4 database with 13 normalized tables (`users`, `resumes`, `resume_contact`, `education`, `experience`, `skills`, `projects`, `certifications`, `achievements`, `languages`, `applications`, `resume_versions`, `sessions`). Enforces foreign key constraints and ACID transactions.
Security & Code Integrity
  • Bcrypt Salted Hashing: Passwords are never stored in plain text. Salt rounds ensure cryptographic protection.
  • Session Fixation & CSRF Defense: Sessions regenerate upon login; double-submit cookie / session tokens defend all state-mutating requests.
  • Parameterized Queries: 100% of SQL statements utilize parameter placeholders (`?`) via `mysql2/promise` to eliminate SQL injection risks.
  • Resource Ownership Enforcement: APIs extract `userId` strictly from validated server session, verifying ownership on every resource before read/write.
  • Rate Limiting & Helmet Headers: Protects against automated credential stuffing and applies strict Content Security Policy directives.
