Quick User Guide

1. Creating & Editing Resumes

From the Dashboard, click Create New Resume. In the Builder, fill in personal details, education, experience, and skills. All changes autosave to MySQL after 1.2s of typing, or click the explicit Save button.

2. Switching Templates

Select any of the 4 templates (Modern, Professional, Minimal, ATS-Friendly) from the top bar dropdown. Your content stays intact, and the live preview updates immediately.

3. Resume Quality Assistant

Navigate to AI Assistant to inspect your Quality Score (0-100), identify passive wording, and paste real job postings to calculate keyword match percentages.

4. Exporting to PDF & Print

Click Download PDF for a high-resolution vector PDF generated server-side by PDFKit, or click Print A4 to preview clean printer-ready pages.

If a user logs out or deletes their account, the session is invalidated instantly in the database, preventing replay attacks. Furthermore, HTTP-only, SameSite cookies cannot be accessed by client-side JavaScript, offering superior defense against XSS token exfiltration compared to storing JWTs in `localStorage`.

For instance, querying student GPA distributions, indexing skills across resumes, or updating a single education record does not require serializing and deserializing a massive JSON payload. Multi-table transactions (`withTransaction` in `db.js`) guarantee atomic consistency when duplicating resumes or managing versions.

Answer: We implement custom CSRF defense in `middleware/csrf.js`. The server assigns a cryptographically random token (`crypto.randomBytes(32)`) attached to the authenticated session and exposes it via an `XSRF-TOKEN` cookie. All state-mutating requests (`POST`, `PUT`, `DELETE`) require the client to supply this token in the `X-CSRF-Token` header. Because malicious cross-origin requests cannot read or attach this header due to the browser's Same-Origin Policy, forged requests are rejected with HTTP 403 Forbidden.

It limits clients to a maximum of 20 authentication attempts per 15-minute window per IP address. When exceeded, the API returns HTTP 429 Too Many Requests with informative retry headers (`RateLimit-Reset`), stopping credential stuffing attacks.

The ATS-Friendly template uses a strict single-column flow, standard semantic heading names (EDUCATION, EXPERIENCE, SKILLS), standard bullet characters, high contrast black-and-white text, and system fonts (Arial/Helvetica), guaranteeing clean sequential machine parsing without lost sections.

When `GEMINI_API_KEY` is provided in `.env`, the server queries the Google Gemini API to offer AI summary rewrites.
